## Interpretations

1. **Directory reads are `read` scope.** `list_users`, `list_teams`, `list_team_members`, `list_team_access` are listed under ADMIN in SPEC 10.2, but a folder manager who is not an owner must pick people and teams in the Share dialog, and an MCP agent following `hub-access` must resolve a user. They require any active user and the `read` scope. Non-owners see only id, name and email of active users; owners also see role, status, teams and last login. `list_team_access` only lists folders the caller can read. All writes stay owner-only (`admin` scope), with team membership also open to that team's maintainers.
2. **Two extra read operations: `list_api_tokens`, `list_mcp_connections`.** The Settings pages need them and SPEC 10.3 forbids UI-only reads. Listing your own token metadata and connections is harmless, so they are ordinary `read` ops on every surface. Minting and revoking stay UI-only.
3. **Sign in, then consent.** SPEC 11.1 orders consent before the Entra redirect. Consent must show the user, which we only know after sign-in, so `/authorize` first ensures a browser session (redirecting through `/auth/login` if needed) and then shows our consent page. The confused-deputy protections are unchanged: per-client consent, browser-bound handle, no framing, `state` single use.
4. **Unpublished documents do not exist for viewers.** `Authz.role()` returns 0 for a document with no published version when the caller is below editor. Lists, search, `get_node` and path resolution therefore never mention it.
5. **"Shared with me" and paths.** List responses only contain readable nodes. Display paths start at the caller's highest readable ancestor (their "shared with me" root), so no unreadable folder name ever appears. Path NodeRefs resolve from those roots. A boundary child folder you have no grant on is hidden from its parent listing; folders granted deeper show up at the top level instead (Drive behaviour).
6. **Unreadable means not_found, before scope.** `authorize()` checks existence first, so a token lacking a scope cannot use `scope_required` versus `not_found` to probe whether a node exists.
7. **Breaking inheritance keeps the manager in.** `set_inherit(false)` by a non-owner adds a direct manager grant for that user if they would otherwise lose access.
8. **Top level is owner-only** for create and move into, since there is no folder to hold a grant. Superseded by 19: the top level is now fixed.
9. **`_hub` is seeded by migration** (`0002_seed_hub.sql`) with `inherit = 0` and an `everyone: viewer` grant, so only owners can edit it. Since 19 it lives at `skills/_hub` and each built-in skill is a skill folder (see 20 and 27).
10. **The `everyone` team** is a row in `teams` (id `everyone`) so it can be granted and listed; membership is implicit for every active user and cannot be edited.
11. **OpenAPI** is generated with zod 4's `z.toJSONSchema` from the registry instead of `@hono/zod-openapi`, which keeps one source of truth without wrapping every route.
12. **Login attempts** (state hash, nonce, PKCE verifier) live in a D1 table `login_attempts` with a browser-binding cookie, swept by cron. KV stays OAuth-provider state plus the 60 s catalog cache.
13. **Audit writes are awaited**, one row per registry call, success or failure (`ok = 0` with the error code). UI-only ops, login, MCP consent and cron also write rows. Keys that can carry bodies (`content`, `markdown`, `patch`, `data_base64`, `zip_base64`, `token`) are stripped before insert.
14. **`export_tree`** returns the zip as base64 JSON so the same op works on REST, MCP and UI. Capped at 50 MB.
15. **Rate limiting** keys on client IP and path prefix, and is skipped when there is no `cf-connecting-ip` (local tests).
16. **Assets** are served with `Content-Security-Policy: sandbox` in addition to SPEC 9 headers.
17. **Etags** are random per write, not content hashes, so two identical saves still detect interleaving.
18. **Audit archiving.** D1 keeps 7 days of audit rows. The cron runs twice a day (03:17 and 15:17 UTC) and moves older rows to R2 as gzipped NDJSON, oldest first, 5,000 rows per file and at most 100,000 rows per run, under `audit/YYYY/MM/DD/<first-id>_<last-id>.ndjson.gz`. Each file is written before its rows are deleted, and a retry overwrites the same key, so a failed run neither loses nor duplicates rows. This replaces the SPEC's 365-day delete. `list_audit` and the Audit page show the last 7 days; older history is read from R2. Retention of the archive is an R2 lifecycle rule on the `audit/` prefix, set per instance.

## Product model: areas, skill folders, links, warnings (November 2026)

The owner approved a new product model with the prototype (`prototype/index.html`), which is its reference for data model, link handling and warning rules. Each point below deviates from or extends SPEC.

19. **Three fixed areas replace a free top level** (SPEC 6.2 "Shared with me" top level, 7 `nodes`). `rules`, `skills` and `documentation` are root folders seeded by `migrations/0003_areas_links_lint.sql` with fixed ids (`...AR1`, `...AS1`, `...AD1`) and an `everyone: viewer` grant each, as in the prototype. They cannot be renamed, moved or deleted, and nobody (owners included) can create another root or move anything to the top level: `create_folder` and `move_node` now require a parent folder, and `authorize()` refuses top-level targets for everyone. Grants and inheritance below the areas work exactly as before. The migration moves every other existing root folder (live or trashed) under `documentation/` with its grants, renaming any root that clashed with an area name to `<name> (old)`, and moves `_hub` to `skills/_hub`. Moves stay inside one area. `list_children` without a folder lists the areas first, in that order.
20. **Skills are folders** (SPEC 7 `is_skill`, 8 frontmatter, 11.2). A skill is a folder under `skills/` that holds a document named `SKILL.md`; it is found by `find_skills` once that `SKILL.md` is published with a valid `name` and `description`. Organisational folders are allowed in `skills/`; a skill folder inside another skill is a sub-skill. Documents under `skills/` must sit inside a skill folder, `SKILL.md` only exists under `skills/` (never directly in the area), and `rules/` holds markdown documents only, with no folders. `nodes.is_skill` is now set only on a published `SKILL.md` with valid frontmatter; `NodeOut.is_skill` on a folder means "contains a SKILL.md". `create_skill` creates the folder and its `SKILL.md` draft in one batch. A skill folder whose `SKILL.md` is unpublished is invisible to viewers, with everything inside it (decided in `authorize.ts`, one more indexed query in the same batch). Documents that were skills before the migration land in `documentation/` and stop being skills until an owner re-homes them; the built-in skills are converted by the migration.
21. **Text files** (SPEC 7, 8: markdown only). Documents named with `.sh .py .sql .js .ts .json .yaml .yml .toml .txt .csv .ps1` are text files (`nodes.format` = the extension, added by migration 0003; everything else is `markdown`, including every pre-existing document). They use the same drafts, versions, diff and publish machinery and the same 256 KB limit, skip frontmatter validation, links and warnings, carry no images, and are allowed only inside a skill folder. They are only ever returned as a JSON string (`get_skill` `markdown`, with `kind: "file"` and `format`), never served with their own content type and never executed. The format follows the name on rename; renames that would break the area rules are refused. Export writes them with their own extension.
22. **`get_skill` reads skill folders, documents and files** (SPEC 11.2 output shape). Given a skill folder, its `SKILL.md`, or a canonical path, it returns `SKILL.md` plus `files` (every readable file of the folder with its path inside the skill, kind and published version; sub-skills are listed as entries, never descended into). For other documents `files` is null and `skill_id` names the enclosing skill. New output fields: `skill_id`, `kind`, `format`, `canonical_path`. There is no separate file-read op: `get_skill` on a file is the read.
23. **`publish_skill`** (new PUBLISH op). Publishes the head version of every changed file of a skill folder (not nested sub-skills) in one D1 batch, so all or nothing, with one audit row listing the files and versions. Files the caller cannot publish are reported `forbidden`, files without versions `empty`, files with uncommitted drafts flagged `has_draft` (drafts are never published). `publish_version` still publishes one document.
24. **Canonical links replace relative links** (SPEC 8 "relative links are resolved on read"). As in the prototype, links are `[[area/path]]` and `[[area/path|label]]` (no `.md`), ignored inside code; relative markdown links are not resolved any more, because the prototype does not use them. Canonical paths: `skills/<skill>/<file>` for anything inside a skill (by the skill's short name, `SKILL.md` dropped), `skills/<parent skill>/<path>` for sub-skills, otherwise `area/folders/name`. Resolution walks the path from the area, and under `skills/` falls back to the shallowest skill with that name. Allowed directions: rules to skills and documentation; skills to documentation and inside their own skill; documentation to documentation. Each link is `ok`, `wrong_direction`, `broken` or `locked` (exists, unreadable for the caller). Locked links never name their target: `href`, `id` and `canonical_path` are null and only the position and label are returned. NodeRefs also accept canonical paths.
25. **`links` table, `get_links`, `get_graph`.** Links are parsed on draft save, discard, commit, publish and unpublish into `links (from_node, kind, ord, to_path, label, to_node)`, where `kind` is `published` or `draft` (the working copy: the draft, else the newest version). `to_node` records the target at write time, but every read re-resolves `to_path`, so links follow renames and later-created targets. Backlinks are found by the target's canonical and full path (indexed on `lower(to_path)`) and filtered by authorization; viewers see published links only, editors their working copies. `get_graph` loads the live tree once into memory (built for a few thousand nodes), collapses files into their skill, returns only readable nodes (viewers: published only) and edges between them with status, plus skill to sub-skill containment edges. `canonical_path` in outputs is null when it would name a folder the caller cannot read (area names are public).
26. **Rules become the MCP `instructions`** (SPEC 11). On `initialize`, the server sends a short usage note followed by the published rules the user can read, ordered by name, frontmatter stripped, whole rules only, capped at 8 KB with a final line saying more rules exist. Other MCP requests skip the query. `get_rules_size` (READ) returns the total, the cap, what is sent and per-rule sizes for the meter.
27. **Search split** (SPEC 15). `skill_fts` now holds only published `SKILL.md` documents of skills (for `find_skills`, which returns the skill folder); a new `doc_fts` holds every other published document and file (raw content) so `search` finds them by content. The migration rebuilds both. The built-in skill text was updated (`hub-authoring` explains areas, links and warnings; `hub-promote` mentions `publish_skill`). `0002` is frozen, so `scripts/gen-seed.mjs` now writes `0004_seed_hub_v2.sql`, which adds the new text as a version and publishes it only where the published version was written by the system; owners' edits are kept. This reaches existing instances too, although that was not required.
28. **Authoring warnings** (not in SPEC). `src/lib/lint.ts` is one pure port of the prototype's `lintAll` with the same rules, codes and messages (`desc-trigger`, `desc-person`, `body-long`, `name-vague`, `name-reserved`, `refs-deep`, `win-path`, `dated`, `rule-long`, `rules-cap`, `rule-procedure`, `toc-missing`; link problems as `link-direction`, `link-broken`, `link-locked`). Lookups (link status for the caller, nested references, total rule size) are gathered before the call. Each warning has `{code, message, key, level}` with `key = code + '|' + fingerprint`: the description for `desc-*`, the link path as written for `link-*`, otherwise the message. Dismissals are stored per node in `lint_dismissals` (no version is created) and apply until the flagged text changes. Warnings never block. They are returned by `update_draft`, `commit_version`, `publish_version` and `publish_skill`, and by `get_warnings`, `dismiss_warning` and `restore_warnings` (all editor and `write` scope); reads (`get_skill`, `get_links`, lists) never carry them.

## Web app and local stack (November 2026)

29. **Dev-only sign-in** (not in SPEC; SPEC 5 is Entra only). `src/auth/dev.ts` adds `GET/POST /auth/dev-login` for the local stack, where Entra cannot run without a tenant. It works only when `DEV_LOGIN` is `"true"` and `BASE_URL`'s host is `localhost` or `127.0.0.1`; otherwise it answers 404. It signs in one of three fixed users (owner Alice Chen, publisher Marcus Webb, viewer Tom Becker; tenant id `dev-local`, object ids `dev-owner`, `dev-publisher`, `dev-viewer`), creating them on first use, with the usual session cookie, CSRF and audit. `DEV_LOGIN` is set only in `.dev.vars`, never in `wrangler.jsonc`. Under the same two conditions the rate limiter is skipped. See SECURITY "Local development sign-in".
30. **`list_children` carries listing extras** (SPEC 10.2 shape extended). Each item may have `skill` (skill folders: name and description from `SKILL.md` frontmatter, version, readable file count, aggregate state `draft`/`unpublished`/`pending`/`published` and the number of files waiting to publish, as the prototype's `skillMark`), `author` and `links` (documents: who wrote the content you see last, and the number of distinct outgoing links), and `children` (plain folders: readable children). All role-aware: viewers get published data and no state. Without them a folder page would need one `get_skill` per row, and every one of those reads would be audited as a skill read. Other ops keep the plain `NodeOut`.
31. **Local demo seed** (`scripts/seed-demo.mjs`). Loads the prototype's Acme content into the local stack only: users and sessions with `wrangler d1 execute --local`, everything else through the REST API as those users (so links, search, warnings and versions are real), then timestamps backdated with SQL, two API tokens and synthetic audit reads like the prototype. It refuses any base URL other than localhost or 127.0.0.1 and never passes `--remote`. MCP connections live in the OAuth provider's KV and are not seeded. The severity matrix image is `scripts/seed-assets/severity-matrix.png`, rendered once from the prototype's canvas code by `scripts/seed-assets/severity-matrix.mjs`.
32. **`wrangler dev --infer-origin-from-routes=false`**. With a route in `wrangler.jsonc`, `wrangler dev` rewrites the request URL, `Host` and `Origin` to the route's host (`https://skills.example.com`), so every cookie mutation failed the same-origin CSRF check against `BASE_URL=http://localhost:8787`. Local runs pass this flag so the Worker sees the real local origin. The check itself is unchanged.
33. **No Tailwind or shadcn/ui** (SPEC 4, 13; the handoff's UI rules). The owner approved the prototype, and fidelity to it is the acceptance criterion, so `web/src/styles/prototype.css` is the prototype's stylesheet copied verbatim (design tokens, light and dark, the phone layout) and the React components render the same class names. `app.css` holds only additions (search page, ProseMirror and CodeMirror surfaces). Icons are the prototype's Lucide paths rendered as React SVG elements, not an icon package.
34. **System fonts instead of Geist.** The prototype loads Geist from Google Fonts. The CSP is `font-src 'self'` and Geist is licensed OFL-1.1, which is outside the allowed MIT/ISC/BSD/Apache-2.0 list, so the SPA ships no web font. The font stack is unchanged (`'Geist','Inter',system-ui,...`), so Geist is used when installed locally and the system UI font otherwise. Recheck if the owner accepts OFL fonts.
35. **Stack: Vite + React 18, a small router and React Query.** Deep links: `/`, `/n/:id` (also accepts a display or canonical path, replaced by the id; a skill folder opens its `SKILL.md`), `/graph?focus=`, `/search?q=`, `/people`, `/teams`, `/teams/:id`, `/audit`, `/settings/tokens`, `/settings/connections`, `/trash`, `/account` (phone), `/login`. SPEC 13 names `/f/:id`, `/d/:id` and `/admin/...`; one `/n/:id` route is simpler because the prototype treats folders and documents as one tree. The viewed version, menus and sheets are not in the URL. A 60-line router replaces React Router (no dependency).
36. **Markdown rendering without rehype-sanitize.** `web/src/lib/markdown.ts` parses with `mdast-util-from-markdown` + GFM and converts the tree into plain data that React renders as text. Raw HTML is never interpreted (it is shown as text), links survive only for http, https, mailto and same-origin paths, images only from `asset://<id>` or `/a/<id>`. There is no `dangerouslySetInnerHTML` anywhere. `test/sanitize.test.ts` runs hostile input through it.
37. **Editor: Milkdown Crepe builder, minimal features.** `CrepeBuilder` (commonmark, GFM, history, clipboard, upload, listener) with only the Placeholder feature. Crepe's toolbar, slash menu, block handle, code-mirror blocks, LaTeX, table UI and image-block are off: the prototype has a fixed toolbar and plain blocks, and image-block would write `![1.00](src "caption")`. SkillHub extensions: `[[links]]` as an inline atom node parsed from and written back verbatim (remark would otherwise escape the brackets), shown as the prototype's chips with status from the server's warnings; an input rule for typed `[[path]]`; a `[[` autocomplete over readable targets allowed by the area rules (from `get_graph` and the skill's files); images keep `asset://` in markdown and display through `/a/`. Raw mode and text files use CodeMirror 6 with the same autocomplete. Frontmatter of non-skill documents is kept untouched outside the editor. The editor chunk is loaded lazily.
38. **Live warnings come from autosave.** The prototype re-linted in the browser every 400 ms. The SPA shows the warnings returned by `update_draft` (every 2 s while typing) and `get_warnings` on open, so they follow the server's rules and link access exactly. Dismissing from the editor or the menu calls `dismiss_warning`; the toast's undo restores all and re-dismisses the others, because the API restores per node.
39. **Draft conflicts.** Autosave passes the etag. On `conflict` a calm sheet names who saved and offers "Keep mine" (save again over their etag) or "Load theirs" (reload the editor with their text). Nothing is merged automatically.
40. **Activity tab and audit are owner-only.** `list_audit` is an `admin`, owner operation, so the drawer's Activity tab is shown to owners only (the prototype showed it to editors) and lists rows for the exact node (the prototype aggregated a folder's subtree). The Audit page's ranges beyond 7 days show what D1 still has (DECISIONS 18).
41. **Things the prototype mocked.** The "Prototype controls" (act as, screens) and the "Preview consent" button are gone: the consent page is the Worker's own (`/authorize`). Export downloads the whole library (`export_tree` has no folder argument) from any folder's More menu for owners. The organisation label next to the product name is `brand.json` `org` when set, else the capitalised first label of the signed-in user's email domain. The Trash entry shows to managers even when the trash is empty.
42. **Search** combines `find_skills` (skills with descriptions, ranked) and `search` (names and published content) in one dropdown, as the prototype's two groups. Enter with no highlighted result opens `/search?q=`.
43. **Counts on the home tiles** come from `get_graph` (skills count skill folders, other areas count documents), which matches the prototype's `areaCount`.
44. **Local and test stack.** `npm run e2e` runs `scripts/e2e-stack.mjs`: build, migrations into a fresh `.wrangler/e2e-<time>` state directory, `wrangler dev` on port 8790 with `DEV_LOGIN=true` and a random `SESSION_SECRET` passed as `--var`, the demo seed, then Playwright (14 tests, serial, shared state). Playwright's Chromium download may be blocked; the config falls back to an existing `ms-playwright/chromium-*` build, then to the installed Chrome (`PW_EXECUTABLE` overrides). `npm run screenshots` writes `docs/screenshots/` the same way.
45. **Usage** (not in SPEC). Successful MCP calls record per UTC day, person and node in `usage_daily`: `get_skill` on the published version counts one load for the skill folder (any file of a skill counts for the skill) or the document; `find_skills` and `search` count every returned node as shown (first 25). Web and REST reads are not counted: the point is what agents find. Drafts and older versions are authoring, not use. Rows are written in the same batch as the audit row and kept 90 days (cleanup cron). `get_usage` (owners, `admin` scope) lists published skills and documentation pages with loads, shown, people, last load, daily loads and incoming published links from outside the node; rules are left out because every agent receives them. The UI adds notes (Never found, Shown never opened, Rarely picked, No links in) that inform and never block. The graph's Usage toggle sizes nodes by 30-day loads and fades unused ones.
46. **Setup guide** on Connections: per-client steps (from CLIENTS.md), the connector URL and Claude Code command to copy, a prompt to try, and whether that client is connected. Shown until dismissed, remembered per browser (`localStorage`), and replayed with the Setup guide button; a dot on the Connections rail icon marks it until then.
47. **Prototypes, a fourth area.** `prototypes/` (migration 0006, fixed id like the other areas) holds folders; a folder with an `index.html` is a prototype, like `SKILL.md` makes a skill. Every file (html, css, js, json, svg, markdown notes) is a document with drafts, versions and publish; `publish_prototype` publishes them together (shared with `publish_skill`). The value is storing, versioning, sharing and linking prototypes, not rendering them: agents with a browser of their own open the signed `preview_url` from `get_prototype` and iterate there, writing back with the normal draft tools. `render_prototype` (Browser Run) is the fallback for clients without a browser and returns the screenshot as an MCP image block, with console messages and page errors. Previews are served from `/p/<token>/` with a sandbox CSP (SECURITY, Prototypes). CDNs are allowed. Links: skills and documentation may link to prototypes; prototype notes link to documentation and prototypes. The graph shows a prototype as one node. The app renders desktop, tablet and phone at their real widths (1280, 820, 390) scaled to fit, so a prototype's breakpoints behave as on the device.
48. **Self-hosting through the binding interfaces.** The Docker image runs the unchanged Worker on Node (`src/node`): it implements the D1, R2, KV, static-assets and rate-limiter interfaces the app already uses, over SQLite (`node:sqlite`) or Postgres (`pg`), local disk or S3 (`aws4fetch`), and a `_kv` table. The app code has no runtime branches except the few SQL statements that differ: full-text search (`ftsSearch` in `db/fts.ts`, FTS5 or tsvector), and a translator for the rest (placeholders, `instr`, byte length). The same migrations run everywhere; on Postgres they are translated (INTEGER to BIGINT, FTS5 tables to generated tsvector columns with GIN indexes, NOCASE to a unique index on lower()). The whole test suite runs on all three targets. MinIO no longer publishes free images, so the bundled S3 store is SeaweedFS.
